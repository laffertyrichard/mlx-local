# Integration architecture for the inspected mlx-local stack

## Reuse and extend

The target is a Swift 6 package for macOS 14+, not a Python web service. Keep LocalLLMCore backend-neutral, LocalInferenceBackends responsible for local preprocessing/transport, and MLXMenu responsible for user interaction and persistence. Do not fork inference routing into a second model server. Workflow orchestration remains distinct from model selection. The existing MCP workflow boundary may later expose the purpose-built workflow; no OpenTakeoff MCP or Prime startup is required.

## Data/control flow

1. **Intake:** user chooses a project-data root and explicit files. Hash and copy originals without overwrite; inventory actual pages/revisions against sheet indexes. Register optional missing references as pending. Native text extraction is an evidence locator, not a boundary detector.
2. **Normalize:** keep original page size/rotation and source hash. Create a frame per rendered page/crop with pixel dimensions, invertible transform and parent frame ID. Each differently scaled detail has its own calibration. Persist source-linked artifacts outside transient inference jobs.
3. **Interpret:** OCR/vision emits bounded candidates: exact quoted label/dimension, witness locations, source/view IDs, uncertainty and alternatives. Never accept pixels as real units without calibration or a source dimension basis. Model coordinates are proposals; do not let a text model calculate authoritative polygons or assign scope silently.
4. **Review basis:** user resolves material source conflicts, physical boundaries, existing/proposed state and witness endpoints. Check independent horizontal/vertical dimensions and face-of-framing versus finished-face datums. No averaging conflicting dimensions, anisotropic rescaling to hide a conflict, or automatic newest-date precedence.
5. **Calculate:** deterministic code calculates accepted area polygons, LF routes, deduplicated EA and dimensional formulas. Keep the existing area helper schema unmodified. Validate set topology per physical plane, including containment, overlap, addbacks and holes. Record known precision versus evidence uncertainty separately.
6. **Draft scope:** pass only selected source facts, accepted/provisional quantity rows and linked exclusions/questions to the local text model. Require a claim-to-source/quantity map. Retained work, removals, relocation, new installation and restoration are separate operations on stable physical IDs. Generic trade knowledge identifies questions, never invented scope.
7. **Review outputs:** generate paired source-linked overlay, workbook/CSV and client/internal scope drafts from one immutable revision snapshot. Cross-check mark/legend correspondence, sorted table integrity, formulas/cached values, quantities, scope wording and register closure. A CSV is not a substitute for a requested recalculated workbook.
8. **Release:** record human approval scope, snapshot digest, actor/date and unresolved items disclosed. Hash changes stale the dependent approval. Design approval does not confer engineering, field, fabrication, procurement or code approval. Preserve prior issued snapshots and a delta report.

Suggested project structure is the included template. The outer project manifest retains existing fields and adds versioned records; separate area plane files still execute with `geometry.py`. The new JSON contracts are a proposed domain boundary and fixtures, not a migration imposed on the existing helper. Claude must implement explicit migration and round-trip tests before changing a real project.

## Local model context and vision limits

Current adapters resize images to a maximum dimension of 4096 unless a profile overrides it; full-sheet downsampling can erase small dimension text. Render an overview for orientation and bounded high-resolution crops for interpretation, with transforms back to the original page. Never calibrate against a resized image without recording its actual frame. Single-image OCR models receive one page/crop at a time. Multi-image metadata is a capability prerequisite, not an accuracy guarantee or justification to submit an entire set.

Route cheap deterministic/text extraction first, then OCR where needed, then focused vision for unresolved candidates, then bounded scope synthesis. Avoid concatenating the entire skill corpus or plan set. Retrieve only the active trade reference and relevant sources, carry stable IDs and short source quotes, and persist intermediate records to disk. Current character-based chunking and advertised context limits do not prove token or visual patch budgets; add explicit bounded input/output accounting with testable truncation/coverage reporting. Reserve output capacity. Repetition or missing-page OCR checks must hold affected items for review rather than treat them as empty.

Memory admission must include weights, measured peaks if available, image patches/KV/cache, temporary rasters and other workload headroom. Registry estimates are approximate and current memory pressure was not observed in this packaging task. Default to sequential preconstruction stages, one model load at a time, user-configurable conservative cap and pause/defer when the pricing workload needs capacity. Reuse the centralized manager, never independently evict/stop another app's worker. Resident/cache size is not free memory; do not infer availability from a saved `unloaded` field. Unknown telemetry stays null. No heavy evaluation on the shared Mac until explicitly scheduled by the user.

## Durability, invalidation and budgets

Existing V3 checkpoints bind source hashes/paths/lengths, request/schema, route/profile, preprocessing/pipeline versions and an artifact digest chain. Reuse those invariants. Current stage-level checkpointing is insufficient for a 200-page OCR stage interrupted after page 199: add atomic per-source/page/crop records, deterministic idempotency keys and a completed-unit index. Resume valid units only. Store user-reviewed domain data separately from the app's bounded inference-job cache (documented retention: 50 jobs, seven days, 1 GiB); expiry of a worker trace must not delete a project's audit history.

Invalidate downstream units when source bytes, page/crop transform, calibration, chosen scope/decision, algorithm, profile or relevant schema changes. Do not silently rerun a corrupt/stale checkpoint. Explain which units are reusable, stale, blocked or incomplete. Checkpoint before revision and after every completed unit. Cancellation should preserve committed units, clean transient rasters and release only owned resources. Test disk-full, interruption during atomic write and stale approvals.

## Permissions and offline behavior

Restrict project roots with symlink-resolved component checks. Read immutable originals; write new derived artifacts and revisions. The existing workflow broker provides actual bounded file reads, but does not yet provide a complete artifact-write/process broker. A descriptor's `writableRoots` or executable list alone does not enforce writes or launch a helper. Implement audited safe output creation, path containment and allowlisted process invocation before exposing those operations. Existing in-process `registerTrusted` handlers are trusted code, not an OS sandbox; use a killable sandboxed child for untrusted plugins. Schema strings in workflow descriptors need real payload validation.

No network for takeoff execution; local workers bind numeric loopback and run offline. Model/provider fallback must preserve local-only, capability and evidence constraints. If no compatible local route exists, pause and report the narrow capability gap. Do not enable cloud fallback, raw attachment egress, downloads or broad shell access. Code/product research is a separately explicit source acquisition step: authorized official documents may be imported and hashed for offline review. If current jurisdiction/adoption/edition cannot be verified, the result is conditional/unresolved. A stored research lead is not current law. Never send an RFI, import to Buildertrend, order, publish or submit from a drafting request.
