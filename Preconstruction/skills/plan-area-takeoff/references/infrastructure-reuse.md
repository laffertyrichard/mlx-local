# Existing infrastructure and reuse

Inventory depicted drains, waste/vent, domestic water, gas, electrical devices/panels/distribution, data/AV/security, HVAC, fire protection and other relevant services. Read actual discipline legends. Architectural fixture symbols establish locations or counts only to the extent shown; they do not establish concealed routes or system completeness.

## Required infrastructure register

| Field | Required content |
|---|---|
| Identity | Stable infrastructure ID, system, item/type, room and associated quantity IDs |
| Evidence | File/revision, sheet/detail, CAD instance path when applicable, and drawing versus field observation |
| Geometry | Located point or depicted route; source frame, physical level, and measured versus schematic/locator status |
| Attributes | Documented size, material, elevation/invert, rating/capacity or circuit/panel; unknown fields remain unknown |
| Existing condition | Depicted existing, observed existing or verified condition, with verification source/date and limits |
| Work disposition | Retain, proposed reuse, relocate, remove, abandon, new, or unresolved; source of that decision |
| Reuse basis | Candidate, specified for reuse, or field-verified for stated purpose; unresolved condition/capacity/connection requirements |
| Dependencies | Related demolition/restoration IDs, trade responsibility, verification action and question IDs |

Keep existence, location confidence, condition and reuse suitability separate. A drawing labeled as-built is not proof of current service condition. A field verification establishes only the attributes actually checked. Do not mark an entire system verified from one observation.

## Routes, counts and connections

- Reconcile physical devices and equipment across plans, risers and schedules. A riser diagram is connectivity evidence, not a scaled route.
- Measure depicted routes only when the drawing establishes a physical path and scale. Keep horizontal runs, documented vertical rises/drops, fittings and connection counts distinct. Label partial lengths; do not extrapolate through missing segments.
- A shown conduit is not a conductor count or wire length. A drain location is not its invert, slope, vent path or available capacity. Proximity to proposed work does not prove a suitable tie-in.
- Use one identity for relocated equipment, with linked existing and proposed locations. A relocation arrow is locator-only and has no measurable service length.
- Record proposed reuse candidates as opportunities requiring confirmation. Source any capacity or compatibility conclusion; do not design missing distribution or declare code compliance.

## Overlay contract

Register discipline sheets to the selected base plan using the plan-comparison procedure. Retain each source frame and report alignment limits; use separate views when alignment cannot be supported.

Use system colors plus labeled line styles for work status and uncertainty; color alone is insufficient. The legend must distinguish actual depicted routes, schematic evidence, location-only points, and proposed relocation arrows. Show no invented line between disconnected symbols. Mark unknown routing as a callout with its question ID, not a plausible-looking path.

Separate dense systems into trade overlays. Keep existing reference counts/lengths outside new installation totals. Include a concise reuse/relocation opportunity list with the evidence, proposed treatment and specific field checks needed. Regenerate affected overlays, connection scope and restoration quantities when verified information arrives.
