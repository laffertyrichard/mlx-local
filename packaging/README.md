# MLX Menu Packaging

This directory contains the static inputs used to build the team-shareable macOS
installer for MLX Menu.

## Contents

- `version.env` — single source for the app release and build versions.
- `resources/welcome.html` — Installer welcome screen.
- `resources/readme.html` — recipient requirements and first-run guidance.

The bundle, component metadata, Distribution XML, and final flat package are generated by
the scripts in `../scripts/`; generated artifacts are written to `../dist/` and are not
committed.

## Build an internal test package

From the repository root:

```bash
./scripts/build-package.sh
```

This produces:

```text
dist/MLX-Menu-<version>.<build>.pkg
dist/MLX-Menu-<version>.<build>.pkg.sha256
```

The default artifact is ad-hoc app-signed and has an unsigned installer. It is suitable
for structural and internal testing, but another Mac will normally reject it through
Gatekeeper.

## Build a team release

A distributable release requires Developer ID Application and Installer certificates plus
a stored notarization profile:

```bash
CODESIGN_IDENTITY='Developer ID Application: …' \
INSTALLER_IDENTITY='Developer ID Installer: …' \
NOTARY_PROFILE='mlx-menu-notary' \
./scripts/build-package.sh
```

The release path fails closed if signing, notarization, stapling, Gatekeeper assessment,
or payload verification fails. Credentials belong in Keychain—never in this repository,
environment files, logs, or command arguments.

## Package contract

The package:

- supports Apple silicon and macOS 14 or newer;
- installs only `/Applications/MLX Menu.app`;
- contains no privileged install scripts;
- does not install Python runtimes or model weights;
- does not add a login item or launch the application; and
- preserves user settings, logs, jobs, and Hugging Face model caches during upgrades.

For signing setup, recipient prerequisites, verification commands, upgrades, rollback,
and the clean-Mac test checklist, see
[`../docs/package-distribution.md`](../docs/package-distribution.md).
