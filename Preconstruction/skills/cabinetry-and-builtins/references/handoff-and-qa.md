# Model, parts and estimate handoff

## Carry intent and evidence together

Use the smallest record sufficient for the task, retaining stable IDs through drawings, model objects, selections, questions and quantities. Suggested fields:

| Record | Useful contents |
|---|---|
| Source/view | Source ID, date/revision, units/datum, field/record/inferred basis, governing scope. |
| Assembly/part | ID, parent cabinet/station, actual role, material/thickness, dimensions/basis, finish/edge/grain and retained/proposed/unknown state. |
| Hardware/appliance | Exact product, regional manual/revision, requirements and unresolved choices. |
| Verification | Check ID, applicable variant/view/state, completed result and evidence, or proposed test with owner/blocker. |
| Release | Concept/coordination/fabrication status, design approvals and separate field/product/qualified signoffs still needed. |

Do not label an estimate list a fabrication cut list. Final parts depend on actual stock, joinery, hardware machining, edge treatment, scribing, tolerances and approved shop details. Carry unresolved dimensions as provisional; no invented precision, zero quantity or silent exclusion. Reconcile part counts and physical allowance ownership without double-counting applied panels or combined fillers/scribes.

## Inspect what will actually be used

Check overall plan/elevation and a section through each critical seat/support/appliance. Show closed and operating/occupied states, source dimensions and local axes. Inspect closeups of each variant's knee opening, mirror/light alignment, front intersections, fillers, returns/ends, toe/grille, hardware intrusion and finish/grain transitions. A whole-room beauty image can conceal these failures. Compare render components with the role ledger and dimension chain, not only a verbal checklist.

Before saying “checked,” identify the artifact/view and observed result. Text-only reasoning is not visual model inspection; a proposed QA view is not a completed test. Saved-artifact readback, appearance acceptance, field fit, operation testing and structural/code approval each establish different evidence. Deliver the recommended concept, meaningful tradeoff, known conflicts and specific release blockers in the user's requested format.
